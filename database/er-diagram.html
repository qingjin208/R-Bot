本次变更说明（v2 → v3）

  • 删除 VISIT（拜访记录）：销售代表的数据全部来自数据库查询，不存在“拜访”事件表。原“拜访材料”升级为 REPORT + REPORT_ITEM（报告批次）。
  • 区域接管对应关系：SALES_REP.region_id 与 CUSTOMER.region_id 都指向 REGION。逻辑为：一个区域内多名销售 ↔ 多个农场（多对多），由区域派生的覆盖关系。
  • 新增报告批次：REPORT(batch_no, rep_id, region_id, generated_at) 记录每次生成的证据包；REPORT_ITEM 把“内部试验 + 外部文献”按条目打包，对应“报告批次信息”。
  • 两层“临床批次”建模：
    • PRODUCT_BATCH（产品批号/lot）：记录每个益生菌生产批次的 cfu_potency 效价、生产/有效期、QC 状态；TRIAL.batch_id 指向所用批次——这是抗生素/益生菌试验“批次=研究菌株与剂量一致性”的关键溯源。
    • TRIAL_BATCH（试验亚批次/入组批次）：同一试验分批入组牛群（enrollment_date / cohort_label / animal_count），ANIMAL.batch_id 归属对应亚批次，支撑分批出数据与区组设计。
  • 保留：CONTACT（农场联系人：肥育场经理/兽医）、ANIMAL、WEIGH_EVENT、METRIC_DEFINITION、审计与约束。

索引与汇总视图（面向“益生菌 vs 对照”报告）

  • TRIAL(product_id)、TRIAL(site_id)
  • TREATMENT_GROUP(trial_id)
  • TRIAL_RESULT(group_id, metric_id) —— 复合索引，覆盖最热路径
  • TRIAL_RESULT(metric_id) —— 跨试验同指标对比
  • METRIC_DEFINITION(metric_code) UNIQUE、PUBLICATION(doi) UNIQUE、ANIMAL(ear_tag) UNIQUE
  • REPORT(rep_id, region_id, batch_no)、REPORT_ITEM(report_id, trial_id, publication_id)
  • 生产环境一律 CREATE INDEX CONCURRENTLY（不能在事务块内执行）。

核心汇总视图（对照组 vs 试验组）：

CREATE VIEW v_trial_efficacy AS
SELECT
  p.product_name,
  t.trial_code,
  ts.site_name,
  tg.group_type,
  tg.dose_rate,
  m.metric_code,
  m.category,
  m.higher_is_better,
  tr.metric_value,
  tr.n, tr.std_dev, tr.p_value, tr.ci_lower, tr.ci_upper,
  tr.measurement_date
FROM product p
JOIN trial t               ON t.product_id = p.product_id
JOIN trial_site ts        ON ts.site_id   = t.site_id
JOIN treatment_group tg   ON tg.trial_id  = t.trial_id
JOIN trial_result tr      ON tr.group_id  = tg.group_id
JOIN metric_definition m  ON m.metric_id  = tr.metric_id
WHERE p.deleted_at IS NULL;

v5 优化审查（本轮已落地）

已采纳的改动：

  • TRIAL_RESULT 冗余 trial_id 外键：与 group_id 同属一个试验；RLS 与 Cube 维度可直接按 trial.data_classification 过滤，无需多跳 join 到 TREATMENT_GROUP。新增关系 TRIAL ||--o{ TRIAL_RESULT（结果明细 冗余路径），并在约束区注明一致性 CHECK。
  • REPORT.data_classification 标注为派生：明确「取所含条目中最敏感级，须保持一致」，消除字段与条目分级的歧义。

保留但需注意同步的冗余（非错误）：

  • TREATMENT_GROUP.dose_unit：前有“补充字段”段落误置在此，实为剂量单位（g/ton、CFU/head），与 dose_rate 成对。
  • PUBLICATION.study_type：RCT / 对照 / 荟萃 / 综述，供 Chatbot 按证据强度排序佐证。
  • ANIMAL.entry_weight / exit_weight 与 WEIGH_EVENT —— ANIMAL 体重作为 WEIGH_EVENT 的缓存副本，由触发器/应用同步。
  • TREATMENT_GROUP.animal_count / TRIAL_BATCH.animal_count 可由 COUNT(ANIMAL) 派生。
  • TRIAL_SITE.city/state 与 CUSTOMER.city/state 农场现场时天然一致（可接受）。
  • TRIAL.product_id 与 TRIAL.batch_id→PRODUCT_BATCH.product_id 一致性（CHECK）。

未采纳（留给你定夺的可省略项）：

  • WEIGH_EVENT：不做纵向生长曲线时，可仅靠 ANIMAL 的入场/出栏体重删掉。
  • TRIAL_BATCH：单批次入组的简单试验可省略，牛只直接归属处理组。
  • REPORT_ITEM 拆两张表：当前「trial_id / publication_id 可空 + CHECK 至少其一」已能表达，暂不拆。
